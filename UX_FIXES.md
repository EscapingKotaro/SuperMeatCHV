# Исправления сценариев CRM

## Блок 1 — выполнено, 12.09.2026

- Вход сохраняет `next` при ошибке, внешние адреса отклоняются.
- Пустой табель без групп не падает; есть переход к созданию группы. Для группы без расписания есть переход к настройке.
- Календарь показывает ошибочную форму; создание задачи из режима редактирования ведёт на отдельную новую форму. Из задачи доступна карточка ребёнка.
- Ошибки тарифа и редактирования сотрудника показаны рядом с полями; введённые данные сотрудника сохраняются.
- Период причины пропуска не перезаписывает посещения и начисления. В карточке доступны история, документы и отмена действующих отметок причины, включая будущие. Посещения и начисления отмена не удаляет.
- Отмена абонемента убрана из меню исторической отметки. Конкретный абонемент редактируется из карточки.
- Из карточки и списка ожидаемых продлений можно открыть оплату выбранного ребёнка. В оплатах доступны архивные дети. Убраны скрытые ограничения списков в 100/300 абонементов.
- Оплата и продление разъяснены как отдельные действия; смена режима учёта требует подтверждения.
- Из прогноза выручки доступны карточка и звонок родителю.
- Возврат из карточки учитывает исходный список; архивирование и восстановление из табеля сохраняют адрес табеля. Открытие редакторов на той же странице переносит текущие параметры фильтров.
- Документы позволяют обновить сроки и комментарий без повторного файла.
- Тренера с активными группами нельзя отправить в архив: предлагается сначала переназначить группы.
- История оплат и зарплаты перенесены в финансовое меню. Уточнены подписи пробников, фильтра клиентов, пустого архива тренеров, настройки сегодняшней даты.
- На сенсорных устройствах касание ячейки открывает меню отметок.

Проверка: 267 Django-тестов прошли с `config.test_settings`; JavaScript проверен через `node --check`, diff — через `git diff --check`. Визуальная браузерная проверка не проводилась. Изменения локальные, без выкладки.

## Блок 2 — выполнено, 12.09.2026

- Сохранение групп и тренеров возвращает к текущим фильтрам; переходы со старых адресов редакторов сохраняют параметры списка.
- Крестик и отмена в редакторах заявок, новичков, групп и тренеров возвращают к списку с фильтрами, без повторного открытия редактора.
- Сохранение новичка сохраняет фильтры. Если не назначены группа, дата пробного, посещение или возраст, переход ведёт к нужному новичку для исправления, с прежними фильтрами.
- Старый URL архивирования тренера больше не позволяет обойти защиту активных групп.
- Общая защита черновиков модальных форм: закрытие, фон, Escape и переходы требуют подтверждения при изменениях. Отказ блокирует также собственные обработчики старых окон. Перезагрузка/закрытие вкладки используют стандартное предупреждение браузера.
- Неизменённые формы и обычная отправка не вызывают предупреждения. Успешное AJAX-сохранение причины пропуска снимает защиту; ошибка сохраняет её.
- Проверка: 270 Django-тестов и 7 Node-тестов защиты форм; синтаксис JavaScript и diff. Без браузерного прогона и выкладки.

## Блок 3 — выполнено, 12.09.2026

- История абонементов: серверная пагинация по 30 записей, общее количество, диапазон и переходы между страницами без скрытого обрезания. Стабильная сортировка по дате начала и ID.
- Поиск по фамилии/имени/отчеству, группе и тарифу; фильтр отменённых и неотменённых записей. Поиск учитывает основную группу у старых абонементов без собственной группы.
- Фильтры сохраняются между страницами и после успешного сохранения на странице оплат. Новый поиск начинает с первой страницы; пустой результат объясняет, что делать дальше.
- Из строки истории можно открыть карточку спортсмена. При поиске и переходах секция истории остаётся раскрытой.
- Ошибка тарифа больше не строит урезанную страницу без платёжных данных. POST привязывается только к отправленной форме, не вызывая ошибок соседнего редактора.
- История и выбор абонемента при оплате независимы: постраничная история не ограничивает список доступных для оплаты абонементов.
- Проверка: 274 Django-теста прошли, включая обход всех 65 тестовых записей по страницам, фильтры, ошибочный номер страницы, ошибки тарифа и возврат после изменения. `git diff --check` без ошибок. Без браузерного прогона и выкладки.

## Блок 4 — выполнено, 12.09.2026

- Форма оплаты больше не получает абонементы всего клуба в HTML: список загружается только для выбранного спортсмена, включая архивного. Отменённые абонементы исключены, лимита 300 записей нет.
- Спортсмен не выбирается случайно первой строкой списка: требуется явный выбор либо переход из конкретной карточки.
- При смене спортсмена прежний абонемент и рабочая группа пробника сбрасываются. Запоздавший ответ для другого спортсмена игнорируется.
- При загрузке, ошибке сети или истёкшем входе отправка заблокирована; доступны пояснение и повтор. Запрос ограничен 15 секундами. Пустой список разрешает предоплату без привязки.
- Новый read-only обработчик требует входа и не допускает кеширования ответа. Серверная проверка принадлежности абонемента при сохранении остаётся действующей.
- Проверка: 276 Django-тестов, 11 JavaScript-тестов. Проверены 305 абонементов одного архивного спортсмена без чужих/отменённых записей, ответы не по порядку, ошибка сети, повтор и предоплата. Без браузерного прогона и выкладки.

## Блок 5 — выполнено, 12.09.2026

- Валидация оплаты вынесена в связанную Django-форму: сумма, дата, спортсмен, принадлежность неотменённого абонемента и рабочая группа пробника.
- Ошибка оставляет модальное окно открытым и показывает ошибки у полей; сумма, дата, спортсмен, абонемент и доступная рабочая группа сохраняются. Нет редиректа с потерей ввода.
- После подгрузки абонементов восстанавливается прежний выбор. Если абонемент стал недоступен, отправка заблокирована до явного выбора другого варианта, включая предоплату.
- Неверный/отсутствующий спортсмен даёт ошибку формы вместо технической страницы. Чужой или отменённый абонемент не принимается.
- Ошибочный платёж не создаётся и не меняет статус/группу пробника. Проверка формы повторяется после блокировки записи спортсмена.
- Минимальная сумма в HTML согласована с сервером: 0,01 ₽.
- Проверка: 278 Django-тестов и 13 JavaScript-тестов прошли; проверены сохранение черновика, исправление ошибки, оплата 0,50 ₽, отказ без записи и восстановление селекторов. Без браузерного прогона и выкладки.

## Блок 6 — выполнено, 12.09.2026

- Отсутствие расписания больше не скрывает спортсменов: вместо пустой сетки показан состав группы с возрастом, абонементом, общим долгом, документами и ссылками в карточки.
- Есть явный переход к настройке расписания. Для периода без занятий пояснение отличается: предлагается выбрать другой период, а не исправлять существующее расписание.
- Архив и сортировки работают в режиме состава через общую выборку табеля. Пустая группа и пустой архив имеют разные сообщения.
- При пустом списке дат нет обращения к несуществующим первому/последнему элементам. Стрелки перехода между занятиями скрыты, если переходить некуда.
- Проверка: 282 Django-теста прошли, включая группу без расписания, архив, пустой день и пустой список сгенерированных дат. Браузерная проверка не проводилась; без выкладки.

## Блок 7 — выполнено, 12.09.2026

- В карточке появился редактор дат и комментария причины пропуска; документ не нужно прикреплять заново, его ссылка сохраняется.
- Новый период применяется к реальным занятиям исходной группы: собственные отметки вне периода удаляются, недостающие внутри создаются, комментарий обновляется. Вид причины не меняется.
- Другие отметки, посещения и начисления блокируют конфликтующее изменение. Ошибка показывает даты и сохраняет черновик формы; изменения атомарны.
- Отменённая причина без отметок не восстанавливается молча. Причина со спорной принадлежностью нескольким группам также не переносится автоматически: показано объяснение.
- Изменение периода записывается в журнал действий. Окно подключено к общей защите несохранённых данных.
- Проверка: 286 Django-тестов прошли, включая перенос периода с сохранением документа, конфликт без побочных изменений, неверные даты и отказ от неявного восстановления отменённой причины. Без браузерного прогона и выкладки.

## Блок 8 — выполнено, 12.09.2026

- Защита черновиков подключена к POST-формам карточки, включая сроки/файлы документов, разряды, группы и поездки, а не только к модальным окнам.
- Переход со страницы и перезагрузка предупреждают о несохранённом вводе. При сохранении одной формы проверяются черновики остальных: они не теряются молча при перезагрузке.
- Сохранение самой изменённой формы не требует лишнего подтверждения. Закрытие модального окна и Escape не вмешиваются в черновик обычной формы карточки.
- Скачивание документов, ссылки на телефон/почту и открытие новой вкладки не сбрасывают защиту и не вызывают лишнего предупреждения.
- Проверка: 287 Django-тестов и 17 JavaScript-тестов прошли. Проверены подключение защиты ко всем POST-формам карточки, сохранение своей/чужой формы, Escape и скачивание. Без браузерного прогона и выкладки.

## Блок 9 — выполнено, 12.09.2026

- В соревнованиях кнопки создания соревнования, дисциплины и участника открывают отдельные чистые режимы. Закрытый редактор прежней записи больше не переиспользуется кнопкой «Добавить».
- Сервер также отделяет новые режимы от соответствующих `edit_*` параметров. Выбранное соревнование сохраняется; формы создания не содержат экземпляр прежней записи.
- Отмена в календаре сохраняет выбранные месяц, день и фильтры, удаляя режим создания/редактирования из адреса.
- Сохранение и отмена лагеря используют общий возврат со снятием параметров редактора. Отмена соревнования также использует чистый адрес списка.
- Проверены расходы: возврат уже сохраняет месяц и категорию, изменений не потребовалось.
- Проверка: 289 Django-тестов прошли, включая три режима создания соревнований при наличии старого edit-параметра и возврат календаря. Без браузерного прогона и выкладки.

## Блок 10 — выполнено, 12.09.2026

- Ручную строку зарплаты можно исправить на месте, без удаления и повторного создания. Редактор ограничен выбранным месяцем, сохраняет ID строки и разрешает оставить прежнего архивного тренера.
- Сохранение и отмена сохраняют месяц. Ошибки показываются у полей и не теряют черновик; обычная форма подключена к защите несохранённого ввода.
- Создание, изменение и удаление ручной строки фиксируются в журнале действий с месяцем, назначением, тренером и суммой; при изменении записываются прежние значения. Запись данных и аудит выполняются в транзакции.
- Выгрузка Excel помечена скачиванием, чтобы не мешать черновику. Права старшего/начальника сохранены.
- Проверка: 292 Django-теста прошли, включая удержание с отрицательной суммой, архивного тренера, сохранение ID, ошибку без изменения записи, чужой месяц и запрет менеджеру. Без браузерного прогона и выкладки.
