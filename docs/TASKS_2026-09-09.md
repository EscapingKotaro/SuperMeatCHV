# Реализация списка «Спартак: СРМ»

Основание: присланный список из 22 пунктов. После уточнения владельца работаем только с локальным кодом. Рабочая БД, сервер, настройки подключения и файлы миграций не изменялись. Новые поля описаны в моделях; существующий процесс выкладки владельца должен подготовить схему до запуска обновлённого приложения. Это не отчёт об успешной production-выкладке.

## Проверка

Тесты выполняются только с `config.test_settings`: отдельная SQLite в памяти, без подключения к рабочей БД и без файлов миграций приложения.

```bash
.venv/bin/python manage.py test crm --settings=config.test_settings --noinput
```

Регрессии покрывают 14-дневную границу, оплаты, сохранение KPI/истории, табель и границу окончания, отмену начисления, источники истины, скидки/snapshot, уведомления, лагеря, скачивание документов, формы и постоянное число запросов для расчётов при росте числа детей/групп. Имеющиеся тесты сертификатов, ролей, пользователей, финансов и соревнований сохранены.

Изменены старые ожидания: уведомление теперь читается явным POST; тест сортировки табеля получает расписание; KPI оплаченного новичка использует реальную связанную оплату.

Браузерная проверка выполняется на временных синтетических данных в памяти, отдельно от локальной рабочей БД. Это не подтверждение поведения на реальной PostgreSQL или реальных данных клуба.

## Запуск автоматического ухода после выкладки

`python manage.py expire_trials` должен вызываться планировщиком каждую минуту под тем же пользователем, с теми же переменными окружения и из той же папки, что и приложение. Команда безопасна для повторного выполнения. Существование активного абонемента без Payment не защищает неоплаченный пробный период.

Шаблоны: `deploy/expire-trials.service.example` и `deploy/expire-trials.timer.example`. В них нужно заменить `__APP_DIR__`, `__APP_USER__`, `__ENV_FILE__` реальными значениями серверной установки и включить таймер обычным процессом эксплуатации. Здесь таймер не устанавливался и не включался. Без него остаётся страховочная обработка при авторизованных запросах, а не независимая фоновая работа.
